# 验证计划：先验证「愿不愿意用」，再谈「做不做得出」

> 当前阶段文档。原则：**在写代码之前，用最轻的方式验证需求**；验证失败的代价是一周时间，做错产品的代价是几个月。

## 1. 待验证的核心问题

> 目标用户是否愿意为一个「AI 生成的实验交互内容」付出**注意力**和**金钱**，且这个意愿足以支撑一个独立产品的留存与付费？

拆成三条可测的假设：

| 编号 | 假设 | 判据（通过线） |
| --- | --- | --- |
| H1 | 教师端对「实验交互内容生成/校验」有真实高频需求 | ≥5/10 位教师在一周内主动二次使用；≥3 位愿意自付或推动学校采购 |
| H2 | 家长端的痛点不在「生成」，而在「可信、省事」 | 家长对「现成可用的实验交互内容包」的付费意愿显著高于「自己生成」工具 |
| H3 | 「内容准确性」是可被感知的价值点 | 用户能区分出「配平错误/参数错误」的样本，并愿意为此选择更可信的产品 |

**H1 与 H2 只留一个作为主线**：哪边先过线就先做哪边，不做「两边都做」的骑墙方案。

## 2. 最小验证实验设计

- **样本**：人工产出 3–5 份实验交互内容（不用产品、不用裸模型直出，人工把关到「可以用」）。
  - 建议组合：初中化学·误差分析型 1 份、初中物理·杠杆/摩擦力 1 份、高中生物·显微观察 1 份、小学科学·家庭低成本材料 1 份。
  - 形态：可拖拽/可操作的网页迷你应用，手机能开，链接直接发。
  - 每份附「知识点—操作—结论」三栏对照，便于评估准确性。
- **对象**：10–20 位（教师 ≥5，家长 ≥5），来源为可触达的教研群、家长群、熟人转介。
- **流程**：发链接 → 观察 15 分钟使用（屏幕录制或陪同）→ 半结构化访谈 15 分钟 → 3 天后回访一次是否再用。
- **时间盒**：**1 周**（3 天产出样本，3 天测试，1 天决策复盘）。
- **记录**：访谈原话、卡点、主动提问、是否转发给别人，全部留档（`docs/验证记录/` 新建目录存放）。

## 3. 决策门

| 结果 | 决策 |
| --- | --- |
| H1 过线 | 走「教师端校验+生成工具」或「B 端能力输出」 |
| H2 过线且家长愿付 | 走「内容组织 + 交互化封装」（本质内容平台，不是生成工具） |
| 两条都不过 | **停止自研产品**，转为技术学习/组件积累，不投入商业资源 |
| 结论模糊 | 不扩功能，换一批用户再测一轮（最多两轮） |

## 4. 明确不做的事

- 不做面向家长的「自由 prompt 生成」入口（合规与准确性双重风险）。
- 不在验证前搭后端、做账号体系、做支付。
- 不与大厂正面比「通用实验生成」覆盖度。
- 不为了演示效果牺牲准确性（宁可不炫，也不能错）。

## 5. 需要同步确认的外部约束

- 目标地区实验操作考试的具体要求与时间表（决定内容优先级）。
- 生成式 AI 服务面向未成年人的合规要求（安全管理制度、内容审核措施）。
- 未成年人个人信息与影像的最小化处理方式。

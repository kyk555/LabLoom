# 工程实践借鉴：从 `D:\code\allweather` 搬什么、不搬什么

> 整理时间：2026-10-20。每条都写了「原路径 / 为什么值得搬 / 落到本项目哪里」，方便以后回查。
> 原则：搬**纪律与方法**，不搬**业务口径**（那边是量化策略，本项目是 K12 实验内容）。

## 一、已直接搬过来（几乎零改造）

### 1. `工具/github_issue.py` + `测试_github_issue.py`

- **原文**：`allweather/工具/github_issue.py`（V1.0，16.6 KB，纯标准库）、`测试_github_issue.py`（21 项离线单测）
- **为什么**：issue 登记 / 回复 / 关闭 / 查询都能在命令行与 AI 对话里完成，不用开浏览器；仓库名从 `git remote origin` 解析，不写死；令牌只走环境变量、不落盘；`--预演` 可离线看将提交的 JSON；关闭必须 `--确认`。
- **本项目改动**：只有两处——`UA` 改成 `labloom-issue-cli/1.0`、文档里的示例命令换成本项目场景。
- **落地**：`工具/github_issue.py`、`工具/测试_github_issue.py`、`工具/README.md`
- **为什么本项目需要它**：验证阶段会产生大量「访谈发现的问题 + 内容错误」，必须有个不会丢的台账；且 issue 正文能强制写「验收标准 / 正确依据」。

### 2. `.clineignore`

- **原文**：`allweather/.clineignore`
- **为什么**：只屏蔽缓存与不入库内容，其余仍可读——避免 AI 上下文被 `__pycache__`、浏览器配置目录（那边有 4 MB 级的 `.pma` 文件）淹没。
- **本项目差异**：额外屏蔽 `docs/验证记录/原始素材/`（访谈影像 / 录音含个人信息）。

### 3. `.gitattributes` 的换行钉死思路

- **原文**：`allweather/.gitattributes`（对生成的 HTML、指纹相关文件 `-text`）
- **为什么**：那边踩过坑——脚本固定输出 LF，clone 后 `autocrlf` 转成 CRLF，跑一次脚本就产生**整文件假 diff**，真实改动被淹没。
- **本项目落地**：`样例/**/*.html`、`报告/**/*.html`、`工具/**/*.html` 按原字节入库；实验素材（png/mp4/pdf）标 `binary`。

### 4. GitHub issue 表单（改造字段，结构照搬）

- **原文**：`allweather/.github/ISSUE_TEMPLATE/{bug_report.yml,feature_request.yml,config.yml}`
- **为什么**：表单强制「复现命令 + 实际输出原文」，把「推测」挡在门外；`config.yml` 关掉空白 issue，把必读文档放最前。
- **本项目改造**：bug 表单的核心字段从「报错栈」换成 **「错误内容原文 + 正确依据（教材 / 课标 / 链接 + 抓取时间）+ 影响级别」**；需求表单加一组**合规自查勾选**（不自由 prompt 直出 / 不采集个人信息 / 必带来源）。

### 6. `readme.md` 的文档骨架

- **原文**：`allweather/readme.md` —— 版本 / 日期 / 基线 → 概述 → 目录结构 → 运行 → 参数 → 常见问题表 → 修改流程 → 风险提示。
- **值得抄的**：**「常见问题」表**（现象 / 原因 / 处理）和**「修改流程」**（改哪测哪）。

## 四、顺带搬过来的「坑位知识」（省时间）

- **必应对长尾查询会静默降级**：HTTP 200 但结果离题——检索结果要判相关性，别直接引用。
- **360 搜索真实 URL 在 `data-mdurl` 属性里**，`href` 是 `/link?m=` 跳转链，不能直接引用。
- **百度反爬**（返回空壳）、**DuckDuckGo 直连失败**、**JS 渲染站（财联社 / 政府网政策页）静态抓只拿到导航壳**——需要时用真浏览器兜底。
- **搜索结果里的旧链接会失效**，当场用取正文工具核对，别隔天再抓。
- **PowerShell 会把命令记进历史、VS Code 会把终端状态写进 `state.vscdb`**——令牌一律从剪贴板读入环境变量，不要手敲明文。

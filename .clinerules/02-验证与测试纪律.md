# 验证与测试纪律

## 一、阶段优先级

**验证实验 > 产品代码**。当前阶段「跑一个访谈」比「写一个功能」值钱。

### 验证实验也算测试，必须可复现

- 每次实验写清：样本清单（版本 / 文件）、对象编号（T1 / P1）、问的问题、观察到的卡点、3 天回访结果。
- 记录**原话**，不要转写成结论（「他说还行」不是数据）。
- 结果写进 `docs/验证记录/<日期>-<轮次>.md`，原始录音 / 截图放 `docs/验证记录/原始素材/`（不入库）。
- 结论必须能被下一步实验推翻；写清「什么结果会让我放弃这条路」。

## 二、写代码后的测试纪律

| 规矩 | 说明 |
|---|---|
| 框架 | `unittest`（**不用 pytest**），测试名用中文：`def test_方程式未配平必须被拦下` |
| 离线 | 测试用临时目录造数据，不读真实素材、不写产物、不发网络请求 |
| 跑法 | `python -B -m unittest <文件>`；中文路径加引号；乱码先 `[Console]::OutputEncoding = [System.Text.Encoding]::UTF8` |
| 断言 | 断言的是**内容正确性**（元素守恒、量纲、因果），不是「函数返回了非空」 |

## 三、校验层规则必须正反例成对

每条规则至少两组用例：

- **该拦的**：错误样本必须被拦下（如 `2H2 + O2 → H2O` 未配平）
- **不该拦的**：正确样本不许误杀（如 `2H2 + O2 →(点燃) 2H2O`）

只写「该拦的」会训练出一个全拒的校验器；只写「不该拦的」等于没校验。

## 四、回归集

- 线上或访谈中发现的每一个内容错误，都进固定用例（`测试_校验.py` 或 `样例/回归/*.json`）。
- 改提示词、换模型、改规则库 → **跑全量回归**，报出通过数 / 失败数与具体失败项。
- 回归集只增不删；要删先说明为什么它不再是有效用例。

## 五、不许做的事

1. **不许为了跑通改期望值**。失败先判断性质：代码回归 / 环境差异 / 数据未同步，分别处理并在交付里说清。
2. **不许自证式测试**（写个测试正好断言当前实现的行为）。做法：把实现改坏，测试必须变红。
3. **不许静默降级**：不新增 `except: pass`、「取不到就跳过」式兜底；缺数据要么报错，要么降级并打印「没有 X，只算了 Y」。
4. **不许拿样本当证据**：3 份手工样本只说明「能做出这种东西」，不说明「用户愿意用」。结论与证据要分开写。

## 六、交付时必须报

- 跑了什么命令、结果如何（通过 / 失败数）
- **哪些没测**、为什么没测
- 只写「应该没问题」视为未验证

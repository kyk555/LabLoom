# 文档与留痕

## 一、文档 vs 产物（先分清再动手）

| | 讲什么 | 格式 | 例子 |
|---|---|---|---|
| **文档** | 「**以后怎么做**」：定位、规则、计划、台账 | Markdown | `README.md`、`docs/0*.md`、`.clinerules/` |
| **产物** | 「**这次是什么**」：给教师 / 家长 / 评审看的东西 | HTML（可双击打开、手机能看） | 实验交互页面、访谈摘要页、对比页 |

- **不写 Markdown 版报告**，也不做 md + html 双份（双份必然一份落后）。
- 产物里**不依赖外网 CDN**：库与样式同层或内联；重要数字放表格前，不靠 hover。

## 二、写作规范

- 一律中文；标题层级不超过三级；表格优先于长段落。
- 数字给单位、口径、比较基准；不确定的写「待核实」，不写估计值冒充实测。
- 版本历史用表格（版本 / 日期 / 变更），当前版本加粗。
- 不新造术语：用 `00-项目总览.md` 的「样本 / IR / 校验层 / 决策门」。
- 改完代码或计划，同步更新对应文档（README 的现状、`docs/01` 的进度勾选）。

## 三、留痕规矩

1. **实验内容**：每份样本带 `依据来源`（教材 / 课标 / 权威链接 + 抓取时间）；引用外部正文另存 sha256。
2. **验证记录**：访谈原话、卡点、回访结果进 `docs/验证记录/<日期>-<轮次>.md`；原始素材不入库。
3. **issue 留痕**：需求与内容错误走 `工具/github_issue.py`（登记 / 回复 / 关闭），正文按 `.github/ISSUE_TEMPLATE/` 字段顺序写；登记前先 `列表 --状态 all` 查重；关闭要 `--确认` 并留验收依据。
4. **Git**：提交信息写清「改了什么 / 为什么 / 影响哪条基线」；
   - 不自动 `git push`、不 `force`、不改仓库配置；
   - 一次提交一件事；不把访谈原文、令牌、真实姓名提交进仓库。
5. **数字不许手改**：报告 / 产物里的数字由脚本现算，改逻辑就重新生成。

## 四、AI 交付格式（固定五段）

① 我理解的需求（复述）→ ② 计划（动哪些文件、影响哪个结论 / 样本）→ ③ 改动（逐个文件说明）→ ④ 验证（跑了什么命令、结果如何）→ ⑤ 风险点与没做的事。

**「AI 生成所以不确定」不是豁免理由**：签批的人必须能解释关键判断（尤其是学科结论）才算交付完成。
